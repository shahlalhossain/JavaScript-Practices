Accidentally Using the Assignment Operator

JavaScript programs may generate unexpected results if a programmer uses an assignment operator (=), instead of a comparison operator (==) in an if statement.


Code Example Sample Output
let x = 0;
if (x == 10)
let x;
if (x = 10)
let x;
if (x = 0)

Expecting Loose Comparison

In regular comparison, data type does not matter. In strict comparison, data type does matter.


Code Example Sample Output
10 == "10";
10 === "10";

Note: Comparing with switch case also uses strict comparison, so a case "10": will not match a value of 10.

Confusing Addition & Concatenation

Addition is adding (numbers). Concatenation is joining (strings).
In JavaScript, both operations use the same + operator.


Code Example Sample Output
let x = 10 + 5;   // x is 15
let y = 10;
y += "5";   // y is "105"

Note: When adding two variables, if one variable is a string, the result will be a concatenation.

Misunderstanding Floats

All numbers in JavaScript are stored as 64-bit floating-point numbers. With floating point calculations you can get small rounding errors.


Code Example Sample Output
let x = 0.1 + 0.2;

To solve the problem above, it helps to multiply and divide.

Code Example Sample Output
let x = 0.1;
let y = 0.2;
let z = (x * 10 + y * 10) / 10;

Breaking a JavaScript String

JavaScript will allow you to break a statement into two lines, but breaking a statement in the middle of a string will not work.


Code Example Sample Output
let x =
"Hello World!";

You must use a "backslash" if you have to break a statement inside a string.

Code Example Sample Output
let x = "Hello \
World!";

Misplacing Semicolon

Due to a misplaced semicolon, this code block will execute regardless of the value of x.


Code Example Sample Output
let x = 0;
if (x == 19); {
  // code block always executes
}

Breaking a Return Statement

It is a default JavaScript behavior to automatically close a statement with a semicolon. Due to this behavior, these examples will all return the same result:


Code Example Sample Output
function myFunction(a) {
  let power = 10;
  return a * power;
}
// JavaScript will also return the same result
function myFunction(a) {
  let power = 10;
  return a * power;
}
// JavaScript will change the result if you break the return statement:
function myFunction(a) {
  let power = 10;   // let power = 10
  return
    a * power;
}

Explanation

JavaScript will, automatically, close the statement at the end of the line, because of the rule of automatic semicolon insertion, since this is what the previous example looks like, after JavaScript has fixed it:
return;
  a * power;
Note: Because of this, it is a common JavaScript practice to put the opening bracket on the same line as the beginning statement, and never break a return statement.

Accessing Arrays with Named Indexes

JavaScript does not support arrays with named indexes. In JavaScript, arrays always use numbered indexes.


Code Example Sample Output
const person = [];
person[0] = "John";
person[1] = "Jane";
person[2] = "Jim";
person.length;   // person.length returns 3

If you use named indexes, JavaScript will redefine the array to a standard object. After that, some array methods and properties will produce incorrect results.

Code Example Sample Output
const person = [];
person["firstName"] = "John";
person["lastName"] = "Jane";
person.length;   // person.length returns 0
person[0];   // person[0] returns undefined

Ending Definitions with a Comma

Trailing commas in object and array literals are legal in ECMAScript 5 (and ECMAScript 3), but can crash Internet Explorer 8 and earlier browsers, and cause a problem if an object (or an array) is converted to JSON, since JSON does not allow trailing commas.


Code Example Sample Output
const person = {
  firstName: "John",
  lastName: "Doe",
  age: 50,
};   // trailing comma after age, legal but not recommended

Undefined is Not Null

JavaScript objects, variables, properties, and methods can be undefined. In addition, JavaScript empty objects can have the value null. This can make it a little bit difficult to test if an object is empty.


Code Example Sample Output
typeof myObj === "undefined"
myObj === null
// You can test for both:
if (typeof myObj !== "undefined" && myObj !== null)

Note: You have to check for typeof first (or wrap in try/catch), because testing myObj === null on an undeclared variable throws a ReferenceError.
