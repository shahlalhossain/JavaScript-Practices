"I Promise a Result!"

"I Promise a Result!"
A JavaScript Promise is an object that represents the eventual completion (or failure) of an asynchronous operation. A Promise is a placeholder for a future result. It starts in a pending state, and settles into either fulfilled (the operation succeeded) or rejected (the operation failed).

Why Promises?

Before Promises, asynchronous code relied on nested callbacks, where each step waits for the previous one using a callback function. Deeply nested callbacks are hard to read and maintain, a pattern often called "callback hell".


Code Example Sample Output
// Callback hell
step1(function(result1) {
  step2(result1, function(result2) {
    step3(result2, function(result3) {
      display(result3);
    });
  });
});

The same flow, with Promises, reads as a flat chain:

Code Example Sample Output
step1()
  .then(step2)
  .then(step3)
  .then(display);

Promise States

A Promise is always in one of these states:


State Description
PendingOperation started, not finished
FulfilledCompleted successfully
RejectedFailed

Note: A Promise is "settled" once it becomes either fulfilled or rejected. A settled Promise never changes state again.

Promises Returned by JavaScript APIs

Many browser APIs, like fetch(), return a Promise immediately, while the actual work (such as a network download) continues in the background.


Code Example Sample Output
fetch("https://example.com/data.txt")
  .then(response => response.text())
  .then(text => display(text))
  .catch(error => display(error));

How then() Works

fetch() returns a Promise. then() registers a callback for when the Promise is fulfilled. JavaScript continues executing the rest of the script. Once the Promise is fulfilled, the registered callback runs.


Code Example Sample Output
const promise = fetch("https://example.com/data.txt");
promise.then(response => response.text());
console.log("This runs before the fetch is done");

Creating a Promise

Syntax
new Promise(function(resolve, reject) {
  // "Producing Code" (may take some time)
  if (success) {
    resolve(value);
  } else {
    reject(error);
  }
});


Parameter Description
resolveFulfills the Promise with a value
rejectRejects the Promise with an error

Note: The function passed to new Promise() should call exactly one of resolve() or reject(). A Promise settles only once.

Example: Create and Use a Promise

This example creates a Promise with a hardcoded success flag, resolving with a success message, or rejecting with a failure message.


Code Example Sample Output
const myPromise = new Promise(function(resolve, reject) {
  let success = true;
  if (success) {
    resolve("The operation was successful!");
  } else {
    reject("The operation failed!");
  }
});

myPromise.then(
  function(value) { display(value); },
  function(error) { display(error); }
);

The then() Method

The then() method takes two functions as arguments: one for when the Promise is fulfilled, and one for when it is rejected. It returns a new Promise, which is why multiple .then() calls can be chained.


Code Example Sample Output
fetch("https://example.com/data.txt")
  .then(response => response.text())
  .then(text => display(text));

The catch() Method

The catch() method takes one function, and is called when the Promise is rejected, or an error is thrown anywhere earlier in the chain.


Code Example Sample Output
fetch("https://example.com/data.txt")
  .then(response => {
    if (!response.ok) throw new Error("Not found");
    return response.text();
  })
  .catch(error => display(error.message));

The finally() Method

The finally() method is called, whether the Promise is fulfilled or rejected.


Code Example Sample Output
fetch("https://example.com/data.txt")
  .then(response => response.text())
  .then(text => display(text))
  .catch(error => display(error))
  .finally(() => display("Finished."));

Promise Chaining

Promises can be chained, with each step building on the result of the previous one.


Code Example Sample Output
function step1() { return Promise.resolve("A"); }
function step2(v) { return Promise.resolve(v + "B"); }
function step3(v) { return Promise.resolve(v + "C"); }

step1()
  .then(step2)
  .then(step3)
  .then(result => display(result))
  .catch(error => display(error));

Returning a Promise

If a then() callback returns a Promise, the next then() in the chain waits for it to settle before running.


Code Example Sample Output
step1()
  .then(value => step2(value))
  .then(result => display(result));

Common Promise Mistakes

Forgetting to Return a Promise: if a then() callback starts another async step but doesn't return it, the chain moves on before that step finishes.


Code Example Sample Output
// Incorrect: step2's result is not returned
step1()
  .then(value => {
    step2(value);   // not returned
  })
  .then(result => display(result));   // result is undefined
// Correct: step2's Promise is returned
step1()
  .then(value => {
    return step2(value);
  })
  .then(result => display(result));

Forgetting to Handle Errors: always add a .catch() at the end of a Promise chain.

Expecting Promises to Block JavaScript: Promises do not pause the rest of your script. Code after a Promise chain keeps running immediately.

Code Example Sample Output
display("Start");

Promise.resolve().then(function() {
  display("Finished.");
});

display("JavaScript continues");

Note: The output order is: "Start", "JavaScript continues", "Finished." The .then() callback always runs after the current script has finished, even if the Promise is already resolved.

Promises and Asynchronous Programming

Promises do not, by themselves, make code asynchronous. They represent the eventual result of operations that are already asynchronous, such as fetch() or setTimeout().

Promises and the Event Loop

Promise callbacks (passed to then(), catch(), finally()) are placed on the microtask queue, and run only after the current synchronous code has finished, via the Event Loop.

Promises vs Callbacks

Promises address several problems with plain callbacks:


Callbacks Promises
Can nest deeplyCan be chained
Error handling is scatteredOne catch() covers the whole chain
Harder to read for complex flowsClearer for multi-step async code

Summary

A Promise has 3 states: pending, fulfilled, rejected. Use then() to handle a fulfilled Promise. Use catch() to handle a rejected Promise. Use finally() for code that must run regardless of outcome. Returning a Promise from a then() callback lets the chain wait for it. Functions like fetch() return Promises.
